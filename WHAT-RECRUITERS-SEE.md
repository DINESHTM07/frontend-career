# What Hiring Managers Google About You (Make Sure It Looks Good)

> When a recruiter is interested in you, they spend 5-10 minutes doing their own research before deciding whether to move you forward. This is what they look at — and what they need to see.

---

## The Hiring Manager's Research Flow

### 1. They search "Dinesh S developer"

Open an incognito browser tab right now and search this. What shows up?

**What you want:** Your LinkedIn profile on the first page. Ideally your GitHub and portfolio too.

**What to do if LinkedIn doesn't appear:** Make sure your LinkedIn URL is customized (linkedin.com/in/dinesh-s — not a random number string), your profile is set to public, and you've added enough searchable content (skills, project names, technologies).

---

### 2. They click your LinkedIn

They spend 60-90 seconds here. They look at:

- **Profile photo** — Is it professional? Clear face, decent lighting, not a cropped party photo. This matters more than it should.
- **Headline** — Does it say what you actually do? "Frontend Developer | React | TypeScript | Next.js" beats "Aspiring Developer" or "ECE Graduate looking for opportunities."
- **About section** — Is it specific? Does it mention what you've built? 3-5 sentences, first person, no buzzwords.
- **Projects/Experience section** — Do they see real work? Live URLs? Brief descriptions of what the project does?
- **Skills** — Are they relevant? React, TypeScript, JavaScript, Git, Tailwind CSS, Next.js — not "Microsoft Word."
- **Recent activity** — Are you posting? Engaging? A dormant profile signals a passive candidate.

---

### 3. They click your GitHub link

GitHub is your code portfolio. They look at:

- **Green contribution squares** — Is there consistent activity? Daily or near-daily commits signal someone actively building. A blank contribution graph is a red flag.
- **Pinned repositories** — Are your best 3 projects pinned? Do they have clear names (not `project1` or `test-repo`)?
- **Repository quality** — Does each pinned repo have: a description, a live URL in the website field, a README that explains what it does and how to run it?
- **Code quality** — If they click into a file, is it readable? Reasonable variable names? Proper folder structure? Or is it one giant 800-line component?

---

### 4. They click your portfolio

They have 15-20 seconds here before they decide to stay or leave.

- **Does it load fast?** If it takes more than 3 seconds, they may have already clicked away.
- **Does it look professional?** Clean design, not cluttered, not a default template with placeholder text still in it.
- **Do the project links work?** Click every single one right now. If a live URL 404s, that's a direct disqualifier.
- **Is it mobile-friendly?** Recruiters often browse on their phones. Open your portfolio on your phone. Right now.
- **Is your contact info visible?** Email, LinkedIn, GitHub — easy to find without scrolling.

---

### 5. They click your live project demos

This is where many candidates lose the recruiter.

- **Does it actually work?** Not "mostly work" or "work on my machine." Work for a stranger who just opened the URL.
- **Does it load fast?** Vercel free tier can cold-start slowly. Test your deployments regularly.
- **Is the data real?** A project that shows placeholder data everywhere looks unfinished.
- **Is it interactive?** If it's a product explorer, can you search and filter? If it's a dashboard, do the charts update?

---

### 6. They look at your code

If they're technical (and many are), they'll open a file or two in your GitHub repo.

They notice:
- Variable names: `handleSearchInput` vs `handler1`
- Component size: one 800-line component vs properly split components
- Import organization: messy random imports vs grouped and ordered
- Comments: none when the logic is complex, or comments everywhere explaining obvious things (both are bad)

You don't need perfect code. You need code that looks like you thought about how to write it.

---

### 7. They check your resume

If they're still interested, they'll look at the resume you uploaded in the application.

- **One page?** For a fresher: yes, one page. Always.
- **No typos?** Read it backwards (seriously — it forces you to see each word individually).
- **Projects with live links?** The URL should be there. Clickable if it's a PDF.
- **Skills match the job description?** ATS systems scan for keywords. If the JD says "React" and your resume says "ReactJS," add both.
- **Clean formatting?** No tables (ATS can't parse them), no columns (same issue), standard section names (Experience, Projects, Skills, Education).

## Weekly Audit Checklist — Do This Every Sunday

Run through this every week while you're in the job hunt. It takes 15 minutes.

```
[ ] Open LinkedIn in incognito mode
    → Does it look professional?
    → Is the headline current and specific?
    → Are all 3 projects listed with live URLs?

[ ] Open GitHub in incognito mode
    → Are green squares showing? (Did you commit this week?)
    → Are 6 repos pinned?
    → Do the pinned repos have descriptions and live URLs?

[ ] Open your portfolio in incognito mode
    → Does it load in under 3 seconds?
    → Do all project links work?
    → Does it look right on mobile? (shrink the browser window)

[ ] Open each deployed project URL
    → Does it load without errors?
    → Does the core functionality still work? (search, filter, charts, navigation)
    → Vercel free tier note: if a project hasn't had traffic in a while,
      it may cold-start slowly — this is normal, but test it

[ ] Google "Dinesh S developer" in incognito
    → Does LinkedIn appear on page 1?
    → Does GitHub appear?
    → Does portfolio appear?
    → Is there anything unflattering you need to manage?

[ ] Check your resume PDF
    → Open it in a PDF viewer (not the editor)
    → Does it look right? Are all links clickable?
    → Is the file named correctly: Dinesh_S_Frontend_Developer_Resume.pdf
```

---

## The 30-Second Test

Give your portfolio URL to someone who doesn't know you. Give them 30 seconds to look at it. Then ask:

1. What does this person do?
2. What have they built?
3. Would you click to see more?

If the answer to #1 and #2 is clear and #3 is yes — you're good. If they're unsure about any of them, something needs to be clearer.

---

*Recruiters are not looking for perfection. They are looking for evidence that you can do the job. Every item on this list is that evidence. Make it easy for them to find it.*
