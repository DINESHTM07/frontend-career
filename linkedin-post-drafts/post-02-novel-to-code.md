I wrote a 250,000-word fantasy novel before I wrote a line of React.

It taught me more about software development than 6 months of tutorials.

Here's what I mean:

**World-building = writing a spec.**
Before I wrote a single scene, I built a world bible — geography, history, magic system rules, character motivations. Every decision had to be consistent with everything else.

That's exactly how I approach frontend architecture now. Design the data model before you write the component. Know the rules before you write the code.

**Daily word count = consistent commits.**
Some days I wrote 2,000 words. Some days I wrote 200. But I wrote every day.

I now commit code every day. Even a small fix. Consistency compounds faster than sprints.

**Editing = refactoring.**
The first draft is never right. The second pass is where it gets good. I've edited chapters three times and still found things to improve.

I now expect my first implementation to be wrong. I write it, make it work, then make it right.

**Finishing = shipping.**
250,000 words. Self-published. Done.

A lot of developers have half-built projects. I learned to finish things before I wrote a single function.

---

The most useful skill in software isn't knowing the right framework.

It's knowing how to start something hard, stay with it, and finish it.

The novel taught me that.
